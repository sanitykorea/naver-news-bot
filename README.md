# 네이버 뉴스 → 텔레그램 채널

키워드로 네이버 뉴스를 검색해 새 기사만 텔레그램 채널로 보낸다.
제목 자체에 기사 링크를 하이퍼링크(볼드체)로 달고, 그 아래 본문 중 키워드가 나오는
문단을 인용구로 붙인다.
네이버 뉴스 페이지(`n.news.naver.com`)가 있는 기사는 나오는 대로 한 건씩 보낸다.
없는 기사는 모아뒀다가 3시간마다(KST 0·3·6·9·12·15·18·21시) 키워드별로 묶어 한 통으로 보낸다.
키워드를 새로 추가하면 그 키워드의 과거 기사가 한꺼번에 몰릴 수 있어, 한 구간에 60건을 넘으면
그 구간은 발송 없이 기록만 한다 (즉시발송 쪽의 `MAX_BURST`와 같은 방지책, 모아보기용은 `DIGEST_MAX`).
보낼 항목이 0건이면 헤더만 있는 빈 메시지도 만들지 않는다. 발송 직전에 라벨 시각을 실제
현재 시각과 다시 대조해서, 다르면(=계산이 어디서 꼬였다는 뜻) 보내지 않는다.

## 녹색당 관련성 필터
"녹색당"이 검색어에 걸려도 실제로 무관한 기사(이름만 스친 기사, 다른 나라 "녹색당" 등)가 섞여
들어온다. 둘 중 하나면 통과: (1) 제목 또는 리드(첫 문단들)에 당이 행위자로 등장 —
"충북녹색당 등 진보 3당은 기자회견을 열고..." 처럼 제목엔 정당명이 안 나와도 리드에서
드러나는 경우까지 포함. (2) `GREEN_PARTY_TOPICS`에 있는 정책 의제와 겹침 — 이 목록은
kgreens.org 전국당 논평 실제 제목에서 뽑았다(추측 아님). 둘 다 아니면 "접점없음"으로 제외.
한계: 외국의 동명 "녹색당"(예: 뉴질랜드)은 리드에 등장하면 행위자 조건을 통과해버릴 수 있다 —
`EXCLUDE["녹색당"]`의 국가 목록에 없는 나라라 못 걸러진다.

## 오래된 기사 재노출
네이버 검색이 `sort=date`인데도 재인덱싱된 옛날 기사가 상위로 다시 뜰 때가 있다(실측: pubDate
7주 전 기사가 그날 처음 검색에 잡힘). 그 링크를 이전에 한 번도 못 봤으면 URL 기반 dedup만으론
"새 기사"로 착각해 보낸다. `search()`에서 `pubDate`를 직접 확인해 `FRESH_MAX_AGE`(24시간)보다
오래된 항목은 애초에 목록에서 빼버린다 — dedup 여지가 아니라 발행 시각 자체로 막는다.

## 모아보기 지연 재검사
모아보기는 3시간까지 큐에 머문다. 그 사이 필터 규칙(BUSINESS_NOISE 등)이 추가돼도
이미 큐에 쌓인 항목은 수집 당시 규칙으로만 걸러진 상태다. 발송 직전에 최신 BUSINESS_NOISE
규칙으로 한 번 더 걸러서, 규칙 추가 전에 쌓인 재고가 그대로 나가지 않게 한다.

## 흔한 단어 키워드 (진보언론 전용)
"기후"·"환경"·"인권"·"노동"은 너무 흔해서 언론사 상관없이 걸면 노이즈가 폭증한다
(실측: 4개 키워드 네이버뉴스 후보 46건 중 진보언론은 3건뿐). `PROGRESSIVE_ONLY_KEYWORDS`에
있으면 `PRESS_TIERS[0]`(경향신문·한겨레·프레시안·오마이뉴스·MBC·JTBC) 매체에서 나온
것만 받는다. 언론사를 모르는 원문 링크(모아보기 경로)는 이 키워드에 한해 아예 보내지
않는다 — 진보언론 여부를 확인할 방법이 없어서다.

`환경`은 추가로 동음이의어 문제가 있다 — "전략 환경이 어렵다"처럼 생태와 무관한
"상황/여건" 뜻으로도 흔히 쓰인다. `RELEVANCE_CHECK`에 등록해서, 진짜 환경 어휘
(기후·탄소·미세먼지·생태 등)가 본문에 하나라도 같이 나올 때만 통과시킨다.

## @workers2016 채널 전달
`@workers2016`(민중언론 참세상의 텔레그램 채널)의 새 글을 하우스 스타일로 옮긴다. 봇이
그 채널 관리자가 아니라 Bot API의 forwardMessage를 못 쓰므로, 로그인 없는 공개 미리보기
페이지(`t.me/s/workers2016`)를 긁어서 글 번호(`data-post`)로 새 글을 판별한다. 보통
"원문 링크 + 제목 + 본문" 형태라 그 셋을 갈라내(`parse_workers2016`) `format_msg`로
그대로 재사용한다 — `[참세상] 제목`을 볼드+하이퍼링크(원문 링크로)로, 본문은 인용구로.
채널 글 자체 링크(`t.me/workers2016/...`)는 보내지 않는다. 원문 링크나 제목/본문 구분을
못 찾으면(원문 링크 없는 자체 작성 글 등) 채널 글 링크를 대신 걸고 첫 줄을 제목으로
쓴다. 상태는 `state.json`의 `workers2016_last`에 마지막으로 본 글 번호만 저장한다.
사진만 있고 텍스트 없는 글은 건너뛴다(텍스트를 못 읽으므로).

## 신뢰 매체 (네이버 미게재)
"민중언론 참세상"(newscham.net)처럼 네이버에 안 실려 언론사·본문을 못 읽는 곳은
`TRUSTED_DOMAINS`에 도메인으로 직접 등록한다. 그러면 3시간 모아보기로 밀리지 않고
즉시발송 대상이 되고, `PRESS_TIERS[0]`(진보언론 최우선)로 취급된다 — 본문을 못 읽으니
인용구 없이 제목·링크만 나간다. 비슷하게 챙기고 싶은 매체가 있으면 같은 딕셔너리에 추가.

## 완전 차단 언론사
`BLOCKED_PRESS`(TV조선·조선일보·주간조선·위키트리·인사이트)는 다른 필터와 무관하게 무조건 제외한다.
경제지 판정과 같은 메커니즘(og:article:author 메타태그)이라 그 태그 없는 언론사 원문
링크(모아보기로 가는 것들)엔 적용되지 않는다.

## 인권위 관련성 필터
"국가인권위원회"/"인권위원회" 검색어가 본문 중간에 다른 기관과 나란히 언급되는 식으로
곁다리로만 등장하는 기사가 많았다("~~ 국가인권위원회와 감사원에 권한을 부여해야" 같은
전문가 코멘트 한 줄). 녹색당과 같은 메커니즘(RELEVANCE_CHECK)을 쓰되, 인권위는 다루는
사안이 너무 다양해 정책 영역 목록으로 봐줄 수가 없다 — 그래서 제목 또는 리드에 "인권위"
(약칭 포함)가 직접 나올 때만 통과시킨다. 실제 인권위 권고 기사는 관례상 제목에 "인권위"가
들어가므로 이 기준으로도 안 놓친다.

## 모아보기 사안 중복 제거
즉시발송(`pick_by_press`)에만 있던 사안 중복 제거가 모아보기엔 없었다 — URL만 다르면
같은 내용이 계속 쌓였다. 모아보기 항목도 같은 `state["topics"]` 목록을 공유해서 중복을
거른다. 언론사를 모르는 링크라(원문 링크) 매체 우선순위 없이 최하위 취급 — 즉시발송
쪽에서 같은 사안이 이미 기록됐으면 모아보기 항목은 걸러진다.

발송 직전 재검사도 이제 요약(desc)까지 포함하고, `BUSINESS_NOISE` 뿐 아니라 AI 질적
필터(아래)까지 다시 통과시킨다 — 큐에 오래 머무는 동안 규칙이 추가됐거나 그때는 AI 호출이
실패했을 수 있어서다.

## AI 질적 필터 (선택)
증권방송 태그("[증시키워드]", "[특징주]" 등)는 매번 이름이 달라서 단어 목록으로 끝이 없다.
`GEMINI_API_KEY`를 넣으면 다른 필터를 다 통과한 후보에 한해 Gemini로 한 번 더 판별한다 —
"이 기사가 시민사회·정치 뉴스인가, 증권시황·기업홍보·행정 이벤트성인가, 아니면 개별
국회의원실의 통상적인(파급력 낮은) 법안 발의 보도자료인가?" 물어서 명확히 아니라고
답할 때만 거른다. 세 번째 카테고리는 "OO 의원, 법 개정 추진" 류의 사안이 사회적으로
중요하지 않은 개별 법안 보도자료를 겨냥한 것 — 차별금지법·노란봉투법처럼 실제 논쟁이
있는 법안은 안 걸린다(확인함).

- 키가 없으면 이 단계는 그냥 건너뛴다(기존 규칙만 적용) — 필수 아님
- 호출이 실패하거나(네트워크 오류, 한도 초과 등) 애매하게 답하면 **통과시킨다** — AI 장애로
  멀쩡한 기사가 안 가는 것보단 낫다는 판단
- 완전 무제한인 모델은 없다. 콘솔에서 확인해보니 이 계정은 flash-lite 계열이 모델별로
  따로 15RPM씩 잡혀 있었다 — 그래서 `gemini-flash-lite-latest`와 `gemini-3.1-flash-lite`
  두 모델을 호출마다 번갈아 쓴다(`GEMINI_MODELS`). 사실상 한도가 2배가 되는 셈이다.
  ([콘솔](https://aistudio.google.com/usage)에서 실제 한도를 직접 확인하는 걸 권장 — 자료와 다를 수 있다)
- 하루 총량(무료 한도 500~1500회, 계정마다 다름)은 우리 사용량(하루 20~100건 추정)에
  여유 있어도, 짧은 시간에 몰아 부르면 분당 한도로 429가 난다 — 특히 모아보기 재검사가
  항목 수십 개를 한 번에 처리할 때. 호출 사이 최소 2.3초 간격(모델당 15RPM, 2모델 교대 기준)을
  두고, 실패(429·타임아웃 등 무엇이든)하면 5초 쉬었다가 **다른 모델로** 한 번 재시도한다
- 무료 발급: [aistudio.google.com/apikey](https://aistudio.google.com/apikey)

같은 `_call_gemini` 인프라(모델 교대·페이스·재시도)를 인용구 요약에도 쓴다. 인용문이
`QUOTE_MAX`(700자)를 넘으면, 그냥 자르는 대신 Gemini로 핵심 문장 1~2개를 원문 그대로
추린다. **이미 다른 필터를 다 통과해 발송이 확정된 항목에만** 호출하므로(후보 전체가
아니라) 호출량이 늘지 않는다 — 그중에서도 인용문이 실제로 긴 경우만 부른다. 키가
없거나 호출이 실패하면 기존처럼 그냥 자른다.

## 경제지·기업 홍보 기사 제외
언론사명에 "경제"가 들어가거나(매일경제·아시아경제·한국경제·서울경제·헤럴드경제 등)
`EXTRA_ECONOMY_PRESS`에 있으면(파이낸셜뉴스) 보내지 않는다. og:article:author 메타태그로
판정하므로 그 태그가 없는 언론사 원문 링크(모아보기로 가는 것들)엔 적용되지 않는다.

제목·요약에 `BUSINESS_NOISE` 단어가 하나라도 있으면 언론사·키워드 상관없이 제외한다 —
증권 시황(증권·주가·강세·특징주·증시키워드 등), 기업 홍보(사회공헌·스폰서십·경영·한전MCS 등),
관공서 홍보(명칭 공모·이름 공모) 세 갈래. 전체 목록은 `bot.py`의 `BUSINESS_NOISE` 참고 —
계속 늘어나서 여기 그대로 옮겨 적지 않는다. 회사명도 같은 목록에 그냥 추가하면 된다
(반복되던 한전MCS가 그 예).

## 포토 기사 제외
제목에 "[포토]"·"[화보]"가 붙은 기사는 사진만 있고 본문이 사실상 없어 보내지 않는다.

## 연예·스포츠 제외
네이버가 연예(entertain.naver.com)·스포츠(sports.naver.com) 기사를 별도 도메인에 두는 걸 그대로 이용한다.
그 도메인이면 검색어가 우연히 걸려도 보내지 않는다. 예: WNBA 트랜스젠더 참여 논쟁, 극장가 BL 콘텐츠 소개 —
성소수자 관련 표현이 실제로 있어도 네이버 분류상 스포츠·연예 섹션이면 제외된다. 판단 기준을 다르게
가져가고 싶으면(예: 이런 기사는 살리고 싶다) `is_ent_sports` 앞뒤로 예외를 추가하면 된다.

## 같은 사안 중복
통신사 기사를 여러 매체가 받아쓰면 제목이 비슷한 기사가 줄줄이 나온다.
단어 겹침 비율(겹치는 단어수 / 짧은 쪽 단어수, `TOPIC_SIM`)로 같은 사안을 묶고, 매체 우선순위를 매긴다.
한국어 제목은 어순이 크게 바뀌는 경우가 많아 문자 n-gram보다 단어 단위 겹침이 더 잘 갈린다.

**비교는 제목이 아니라 본문 전체로 한다.** 같은 행사를 취재해도 언론사마다 다른 발언을
헤드라인으로 뽑으면(예: 추미애 경기지사의 한 연설을 두고 4개 매체가 전부 다른 인용문을
제목으로 씀) 제목만 비교해선 최대 유사도 0.29로 하나도 안 묶였다. 본문 전체로 비교하면
같은 사안 최소 0.57 / 무관 기사 최대 0.13으로 확실히 갈린다. 언론사를 몰라 본문을 못
읽는 모아보기 경로는 제목+요약으로 비교한다(본문 비교보다는 약함).

| 순위 | 매체 |
|---|---|
| 0 | 경향신문, 한겨레, 프레시안, 오마이뉴스 |
| 1 | 연합뉴스, 뉴시스, 뉴스1 |
| 2 | 그 외 |

한 사안은 한 번만 보낸다. 단:
- **더 우선하는 매체**가 뒤늦게 나오면 다시 보낸다 (그 외 매체 → 나중에 한겨레면 한겨레도 발송)
- **"[단독]" 표시가 붙은 제목**은 같은 사안이라도 새 사실관계로 보고 다시 보낸다
- 그 외(진보언론끼리 같은 사안을 반복 보도하는 경우 포함)는 이미 보낸 사안이 또 오면
  보내지 않는다 — 진보언론(순위 0)이라고 예외를 두지 않는다. 예전엔 진보언론은 무조건
  다시 보냈는데, 네팔 홍수·용혜인 후보자 관련 기사처럼 같은 사안을 여러 진보언론이
  각각 다뤄 피로도만 쌓이는 사례가 많아 없앴다.

## 설정
```
cp .env.example .env
```
`.env` 에 값을 채운다. `.gitignore` 에 있어 커밋되지 않는다.

- `NAVER_ID` / `NAVER_SECRET`: NCP 콘솔 > AI·NAVER API > Application > 인증 정보
  (NCP 발급 키는 `naverapihub.apigw.ntruss.com` + `X-NCP-APIGW-*` 헤더를 쓴다.
   developers.naver.com 키라면 `openapi.naver.com` + `X-Naver-Client-*` 로 바꿔야 한다)
- `TG_TOKEN`: @BotFather
- `TG_CHAT`: 숫자 채널 ID. 봇을 채널 관리자로 넣고 아무 글이나 올린 뒤 `python3 bot.py --chatid`
- 키워드는 `.env` 가 아니라 `keywords.txt` 에서 관리한다 (한 줄에 하나, `#` 은 주석)

## 실행
```
python3 bot.py            # 발송
python3 bot.py --check    # 키 인증 점검 (값은 출력하지 않음)
python3 bot.py --chatid   # 채널 숫자 ID 확인
python3 bot.py --test     # 필터·인용 로직 자체 점검
```
첫 실행은 발송 없이 `seen.json` 만 만든다(과거 기사 폭탄 방지).

## 해외 기사 제외
`EXCLUDE` 에 키워드별 제외어(국가명·한자 약칭·주요 도시)를 둔다. 판정은 3단계:

| 위치 | 처리 |
|---|---|
| 제목에 있음 | 제외 |
| 리드(첫 `LEAD_PARAS` 문단)에 있음 | 제외 |
| 본문 전체 `MENTION_LIMIT` 회 이상 | 제외 |
| 그 외 | 통과 (비교 사례로 한두 번 언급된 경우) |

제외된 기사는 실행 로그에 사유와 함께 찍힌다. 세다 싶으면 두 숫자만 올리면 된다.

단, 키워드 자체(예: "녹색당")가 `FOREIGN_OVERRIDE_MENTIONS`(4)회 이상 나오면 국가명 제외를
무시하고 통과시킨다 — 해외 정당을 "OO 녹색당"으로 여러 번 부르는 경우까지 걸면 과도해서다.
2였을 때는 "영국 진보 정당 녹색당의 대표는..." 처럼 해외 정당을 소개만 해도 2회를 넘겨
뚫렸다 — 실제로 그렇게 새서 4로 올렸다.

같은 `EXCLUDE` 메커니즘을 국가명 말고 다른 단어에도 쓸 수 있다 — `청소년 SNS`/`청소년 스마트폰`엔
"소송"을 넣어 메타·틱톡 등 해외 빅테크 상대 집단소송 뉴스를 막는다. "소송" 자체는 인권·노동
기사에 흔한 말이라 전역으로는 안 막고, 이 두 키워드에만 국한했다.

## 자동화 (GitHub Actions)
`.github/workflows/news.yml` — GitHub `schedule`은 지금 꺼두고 외부 크론(cron-job.org 등)이
`workflow_dispatch`를 2분마다 호출한다(GitHub 자체 스케줄러는 부하 시 지연이 심했다).
상태(`seen.json`, `state.json`)는 커밋 대신 Actions 캐시에 보관한다.

캐시는 **고정 키(`seen-state`) 하나**를 매번 지우고 다시 저장하는 방식이다 — 실행마다
새 캐시를 만들던 예전 방식은 하루 만에 수천 개가 쌓여서, `restore-keys`가 엉뚱한 옛날
스냅샷을 물어와 오래된 기사가 "새 기사"로 재발송되는 사고로 이어졌다. 이 방식을 쓰려면
워크플로에 `permissions: actions: write`가 있어야 한다(캐시 삭제 권한).

저장소 Settings > Secrets and variables > Actions > Secrets 에 4개 등록:
`NAVER_ID` `NAVER_SECRET` `TG_TOKEN` `TG_CHAT`

키워드는 비밀값이 아니므로 Secrets 대신 `keywords.txt` 를 직접 고친다 —
GitHub 저장소에서 그 파일을 열어 연필 아이콘으로 편집 후 커밋하면 다음 실행부터 바로 반영된다.
